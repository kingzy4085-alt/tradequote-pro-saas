# TradeQuote PRO - Project Rules (Ingzys Automation)
- Stack: Next.js 14.2 (App Router), TypeScript, Tailwind CSS 3, Supabase (Postgres + Auth + RLS + Storage), Stripe, Resend, Twilio. AI: Anthropic Claude (AI CEC Assistant, model from `env.anthropicModel()`), Google Gemini `gemini-2.5-flash` (voice-to-estimate and scope extraction, `GEMINI_API_KEY`).
- Domain: B2B SaaS for electrical & industrial shutdown contractors (tradequotepro.com), Canada. Tiers: Solo ($49/mo CAD), Shop/Crew ($99/mo CAD).
- Core Modules: Quote Pipeline & Assemblies, Voice-to-Estimate, Client Portal, Timecards, Change Orders, Daily/Tailgate/LOTO Safety Logs, WCB Tracking, AI CEC Assistant.
- Efficiency Rules:
  1. Read only target files; never scan node_modules, .next, .worktrees, .claude/worktrees, or full directory trees unless asked.
  2. Preserve Supabase RLS policies and .env.local keys (NEXT_PUBLIC_SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, ANTHROPIC_API_KEY, GEMINI_API_KEY, STRIPE_SECRET_KEY). Never print secrets.
  3. Verify TypeScript/imports with npm run build before finishing multi-file edits for Vercel.

## Specialist agent team (`.claude/agents/`)
Delegate to the matching specialist; run independent specialists in parallel. Each agent's file holds its full rules.

| Agent | Owns | Use when |
|---|---|---|
| `supabase-migration-specialist` | `supabase/migrations/`, RLS, RPCs, grants, `lib/modules.ts` ↔ generated SQL | Any schema, policy, function, index or storage change; RLS reviews |
| `nextjs-frontend-builder` | `app/**`, `components/**`, print views, portal | New/changed pages, estimate editor UX, mobile field screens |
| `voice-estimate-pipeline` | `lib/voice-estimate.ts`, `app/api/ai/*`, recorder/scope components, assembly mapping | Audio, transcription, AI extraction, prompts/schemas, AI rate limits |
| `cec-compliance-auditor` (read-only) | Safety records, CEC/AI guidance, WCB, signatures, disclaimers | Before merging anything touching safety records, code guidance or AI output; returns PASS / PASS WITH NOTES / BLOCK |

Routing rules:
- A feature spanning layers goes schema → API/pipeline → UI: migration specialist first, then pipeline/frontend.
- Any change to LOTO/tailgate/inspection records, the AI Assistant prompt, or AI-generated estimate content must get a `cec-compliance-auditor` pass before it is called done. A **BLOCK** verdict means fix before merge.
- Agents write migration files but never apply them to a remote Supabase project unless the user explicitly asks.

## Non-negotiables
- **Tenant isolation is enforced by RLS**, not app code: every tenant table has `company_id default public.user_company_id()`, RLS on, and policies using `user_company_id()`, `user_rank()` and (for writes) `company_can_write()`. Role ranks: owner 5, admin 4, project_manager 3, foreman 2, electrician 1 (`lib/roles.ts` ↔ `public.role_rank()`).
- Migrations: `supabase/migrations/<14-digit version>_<name>.sql`, idempotent, functions `set search_path = ''`. `20261101000000_saas_core.sql` and `20261104000000_registry_sync.sql` are generated by `npm run db:generate` from `lib/modules.ts` — never hand-edit. `database/legacy/` is historical only.
- Safety records are append-only signature state machines. `public.safety_record_rules` (SQL) and `lib/records.ts` must change together; `tests/safety.test.ts` checks parity.
- AI output is always a draft the contractor reviews: nothing AI-generated is auto-saved or auto-sent. Voice lines carry `price_source` (`spoken` / `assembly` / `none`); never invent supplier prices or permit fees.
- CEC (CSA C22.1) and other CSA standards are copyrighted: summarise, never reproduce text or tables. Never fabricate rule numbers; point safety/compliance answers to the AHJ or engineer of record.
- API routes: `requireApi({ minRank, write })`, `readJson()` + zod, `jsonError()` with plain-language messages. Paid AI calls stay behind auth, size caps and `consumeUserRateLimit(..., 'ai')`.
- UI: field-first — dark slate-950 theme, amber focus, ≥48px touch targets, Canadian spelling, reuse `components/ui.tsx`.

## Build verification (same gate as `.github/workflows/ci.yml`)
Run before declaring multi-file work done, in order:
1. `npm run db:check` — migration versions unique and well-named
2. `npm run typecheck`
3. `npm test` — vitest (includes PGlite DB tests)
4. `npm run build` — runs `scripts/check-env.ts` then `next build`
Report failures with their actual output; don't mark work done while any step fails.
